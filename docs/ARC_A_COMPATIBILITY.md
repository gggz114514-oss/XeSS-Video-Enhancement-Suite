# Arc A 系列兼容模式（R4.2）

## 使用

关闭 ComfyUI，在本节点目录执行 `git pull --ff-only`，然后重启 ComfyUI 并刷新浏览器。程序会下载和校验匹配的 Runtime R4.2，不需要自行覆盖 EXE 或安装 Python 依赖。

选择 **GPU Block（快速）**、**GPU DIS（实验）** 或 **AMD 光流（实验）** 后，三个 R4 视频节点都会出现 **Arc A 系列兼容模式**：

- A770 等 Arc A 系列遇到整幅绿/紫色竖条或异常偏色时，开启后重新处理。
- 默认关闭；原画面正常时无需开启。不是按显卡名称自动切换，也不是所有 A 系列都必须开启。
- CPU DIS 和 Intel 视频接口不走这里的 NV12→D3D12 共享入口，不提供此开关。
- 「抗竖纹」是另一项超分画质保护滤镜，不能用来修复这里的颜色/纹理互操作错误。

原有 R4 工作流不提供新字段时按关闭处理；不会自动改变倍率、光流、深度、Mask、五帧融合、锐化或编码器。R4.1 先提供了 GPU Block 的兼容开关，R4.2 补齐另外两条共用入口的 GPU 算法；AMD 光流是算法名称，不代表仅用于 AMD 显卡。

## 原理与验证边界

原路径直接将解码后的 NV12 纹理共享给 D3D12。兼容路径在 D3D11 GPU 上转为普通 RGBA 纹理再共享，避免跨 API 共享 NV12。没有新增全帧 CPU 回读转换；最终使用软件编码器时仍按原设计在输出边界回读。

A770 用户反馈此兼容路径解决异常。维护者测试机是 **B580 / 32.0.101.8974**，不能将 B580 回归写成所有 A 系列驱动均已验证，也不将单一症状断言为所有硬件的唯一根因。

GPU Block 兼容候选在 B580 的验证包括 SR/FG/SR→FG、QSV 与 x264、完整 311 帧 SR / 621 帧 SR→FG、1000 帧运行、取消与异常退出、中文/空格路径。原/兼容完整成片哈希一致。48 帧配对测试中，720p SR 的处理循环增加约 0.105 ms/输入帧；其他场景大多在波动范围内。这不是 A770 的性能承诺，也不能套用为 GPU DIS / AMD 光流的性能数据。

GPU DIS 的兼容输入额外执行与原路径相同的整数 RGB→灰度公式，保持运动估计语义；AMD 光流继续读取公共 RGBA 输入。新增两路的回归证据分别记录，不沿用 GPU Block 的长跑结论。

发布版本保持输入边界：8-bit H.264/HEVC 4:2:0 SDR；HDR、全范围及不支持的输入仍会明确拒绝，不静默转码降质。

## 曾使用诊断包的用户

诊断 ZIP 不是长期更新源。此次应更新节点并使用清单锁定的正式 Runtime R4.2，不再把候选 EXE 反复覆盖回新运行库。程序按版本保留原运行库，不修改 ComfyUI 本体及其 Python 包。

如果自行设置了 `XESS_RUNTIME_ROOT`，节点会使用该外部运行库并跳过自动部署；请取消此覆盖或明确指向匹配 R4.2 的完整运行库。网络不可用时，可下载本版本 Release 的运行库 ZIP，通过 `install_runtime.bat -AssetPath "ZIP完整路径"` 安装。不要把 ZIP 覆盖到 ComfyUI 根目录。

遇到 Git 本地修改/历史分叉，先备份，不强制覆盖；参见 [升级与回退](COMFY_R4_UPGRADE.md)。报错反馈请包含显卡/驱动、原路径与兼容路径结果、`plan.json`、`command.json`、`native.json` 和 `native.log`。分享前可遮去个人路径，不需要上传原视频或模型。
